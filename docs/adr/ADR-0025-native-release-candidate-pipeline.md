# ADR-0025: Native release-candidate pipeline

- Status: Accepted
- Date: 2026-08-22
- Owners: project maintainers

## Context

ADR-0014 requires Linux x86-64/arm64, macOS x86-64/arm64 and Windows x86-64
artifacts, signed checksums, an SBOM and build provenance. The Gitea runner
fleet does not provide all five native hosts. The private GitHub mirror does
provide pinned native hosted images for every required architecture, including
both Apple architectures, without cross-compiling or redistributing an Apple
SDK. A project signing identity must remain recoverable under maintainer
control rather than belonging only to one automation service.

## Decision

Release candidates use annotated OpenPGP-signed tags named
`v<version>-rc.<number>`. The tag version and Cargo workspace version must
match exactly. Lightweight or unverifiable tags fail closed. The public key is
committed as `docs/release-signing-key.asc`. The armored private key and its
passphrase exist only as independently encrypted Ansible Vault values and as
GitHub environment secrets populated from that vault. They are never written
to a runner artifact or to repository plaintext.

Each supported target is built and tested on a native runner:

| Target | Required runner label |
|---|---|
| `x86_64-unknown-linux-gnu` | `ubuntu-24.04` |
| `aarch64-unknown-linux-gnu` | `ubuntu-24.04-arm` |
| `x86_64-apple-darwin` | `macos-15-intel` |
| `aarch64-apple-darwin` | `macos-15` |
| `x86_64-pc-windows-msvc` | `windows-2025` |

Native builds avoid redistributing platform SDKs and allow target filesystem
tests to execute. A runner must report the exact expected host target; an
emulated or silently cross-compiled build is rejected.

Every job uses the locked Rust 1.88.0 toolchain, runs tests, builds the release
binary from the clean signed tag and emits a deterministic platform archive.
The archive includes license/notices, changelog, migration/rollback guide,
compatibility matrices, a CycloneDX JSON SBOM generated by pinned
`cargo-cyclonedx` 0.5.9 and a redacted provenance statement. A final Linux job
recomputes SHA-256 for the complete artifact set, signs `SHA256SUMS` and
verifies that signature before publication.

The GitHub main workflow exercises all five native hosts without signing or
publishing. Only an exact OpenPGP-signed RC tag activates packaging; all five
native artifacts and the multiarch OCI archive must reach one final job before
the checksum manifest can be signed and published as an immutable prerelease.
The legacy Gitea self-hosted workflow is manual-only and cannot consume tags.

## Consequences

GitHub-hosted macOS minutes cost more than Linux minutes, but remove the
availability and patching burden of dormant privileged host runners. Ansible
Vault remains the recovery authority for the signing identity; GitHub receives
only the three environment secrets required for a tag build. The pinned
immich-go binary remains the operational rollback.

## Verification

Push CI validates release scripts and documentation and builds/tests all five
native targets without accessing signing material. The release workflow
verifies the tag and clean tree before any build, rejects a host/target
mismatch, and validates every archive/SBOM/provenance digest. Publication is
possible only after the detached checksum signature verifies against the
committed public key.
