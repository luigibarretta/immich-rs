# ADR-0025: Native release-candidate pipeline

- Status: Accepted
- Date: 2026-08-22
- Owners: project maintainers

## Context

ADR-0014 requires Linux x86-64/arm64, macOS x86-64/arm64 and Windows x86-64
artifacts, signed checksums, an SBOM and build provenance. The current Gitea
installation has only a Linux x86-64 container runner and no project release
signing identity. Cross-compiling macOS with an unprovisioned Apple SDK would
introduce licensing and reproducibility risk. Generating an unattended private
key would also make the automation, rather than the maintainer, the release
identity.

## Decision

Release candidates use annotated OpenPGP-signed tags named
`v<version>-rc.<number>`. The tag version and Cargo workspace version must
match exactly. Lightweight or unverifiable tags fail closed. The public key is
committed as `docs/release-signing-key.asc`; the private key exists only in a
protected Gitea release secret and is never written to the repository or an
artifact.

Each supported target is built and tested on a native runner:

| Target | Required runner label |
|---|---|
| `x86_64-unknown-linux-gnu` | `docker` |
| `aarch64-unknown-linux-gnu` | `linux-arm64` |
| `x86_64-apple-darwin` | `macos-x64` |
| `aarch64-apple-darwin` | `macos-arm64` |
| `x86_64-pc-windows-msvc` | `windows-x64` |

Native builds avoid redistributing platform SDKs and allow target filesystem
tests to execute. A runner must report the exact expected host target; an
emulated or silently cross-compiled build is rejected.

Every job uses the locked Rust 1.88.0 toolchain, runs tests, builds the release
binary from the clean signed tag and emits a deterministic platform archive.
The archive includes license/notices, changelog, migration/rollback guide,
compatibility matrices, a CycloneDX JSON SBOM generated by pinned
`cargo-cyclonedx` 0.5.9 and a redacted provenance statement. A final Linux job
recomputes SHA-256 for the complete artifact set, signs `SHA256SUMS` and
verifies that signature before publication.

The tag workflow remains unavailable until all five runner labels, the public
key and protected signing secret are provisioned. Missing prerequisites are a
release blocker, never a reason to skip a target, publish unsigned output or
create a key automatically.

## Consequences

Phase 6 can prove application and scale gates before release infrastructure is
available, but it cannot claim a release candidate. Native runner and signing
provisioning require an explicit security/operations decision by the
maintainer. The pinned immich-go binary remains the operational rollback.

## Verification

Push CI validates release scripts and documentation without accessing signing
material. The release workflow verifies the tag and clean tree before any
build, rejects a host/target mismatch, runs the full target tests and validates
every archive/SBOM/provenance digest. Publication is possible only after the
detached checksum signature verifies against the committed public key.
